# SiteCommand — Claude Code Project Context

## What this is

**SiteCommand** is Velron Digital's **white-label sales demo** of its Operations
Intelligence Platform (a de-branded fork of a client production app). It exists
so prospects can click around a fully working product with realistic data:
from the public demo entry page, a visitor enters as any role (Executive,
Project Manager, Site Supervisor, Workshop Manager, SHEQ Officer, Client) and
uses every feature.

It is linked from velrondigital.online as a live demo. Treat it as a polished
showroom, not an internal tool.

## Architecture (important, different from the production app)

- **Frontend-only. There is NO backend.** No Supabase, no API keys, no env vars.
  Never add network calls or secrets.
- All data lives in **`src/demo/db.ts`**: an in-memory store seeded with ~30
  days of plausible multi-site mining/TSF operations data (5 sites, 4 TSF
  facilities, 17 assets, SHEQ records, certificates, a meeting pack, demo
  personas). A seeded PRNG keeps numbers stable between builds.
- Every module in **`src/lib/`** reimplements the production app's exact API
  surface over that store. **Pages are unchanged from the production app**, so
  keeping lib signatures stable is what keeps this fork cheap to maintain.
- Mutations work for the life of the tab (submit reports, log breakdowns, add
  certificates, upload documents as object URLs). **Refreshing resets the demo.**
- Auth (`src/state/AuthContext.tsx`) is a persona switcher: `loginAs(userId)`
  from the role cards on `src/pages/Login.tsx`, persisted in sessionStorage.
- "AI" meeting packs are generated by a canned writer in `src/lib/meetingPacks.ts`
  that pulls live figures from the context summary (1.6s fake delay). No xAI.

## Branding rules

- Product name: **SiteCommand** (text wordmark in `src/components/Brand.tsx`,
  no logo image). "Built by Velron" / Powered by Velron stays everywhere.
- Palette: **dark blue / white**. The primary Tailwind token is still named
  `billnick` (historical) but its values are the blue ramp, do not rename it
  across the codebase, and do not reintroduce orange.
- **No real client names anywhere** (no Billnick, no real sites/people). Demo
  sites are fictional: North Ridge, Falcon Creek, Silver Plains, Eastgate +
  Head Office. Personas are fictional.

## Conventions

- Vite 5 + React 18 + TS strict + Tailwind 3.4 + recharts + lucide. Same
  definition of done as production: `npm run build` clean, everything clickable,
  responsive at 360px/1440px.
- Deploy: static site on Vercel (SPA rewrites in `vercel.json`), no env vars.

## Things to preserve when editing

- The demo must always look **alive on first load**: production trending, one
  site below target (Eastgate), one TSF below its advisory freeboard (Falcon
  Creek), one overdue SHEQ item, one expired + one expiring certificate, two
  active breakdowns. If you change seeds, keep those storytelling beats.
